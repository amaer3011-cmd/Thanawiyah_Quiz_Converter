# 🎯 بوت تليجرام لتوليد الكويزات التعليمية

بوت يحوّل أي مصدر تعليمي (رابط يوتيوب، ملف صوتي، صورة، PDF، أو ملف HTML)
إلى كويز تفاعلي كامل بنفس تصميم قالب **Thanawiyah_Quiz🎯** الأصلي، مع أسئلة
تعتمد على الفهم والتحليل والاستنتاج، وشرح تفصيلي للإجابات الصحيحة والخاطئة.

---

## 1. هيكل المشروع

```
quizbot/
├── bot.py                  # نقطة الدخول - منطق البوت والمحادثة
├── config.py                # قراءة الإعدادات من .env
├── gemini_client.py          # عميل Gemini مع دعم عدة مفاتيح API
├── content_extractor.py      # استخراج نص من يوتيوب/صوت/صورة/PDF/HTML
├── quiz_generator.py         # توليد أسئلة الكويز عبر Gemini
├── html_builder.py           # حقن الأسئلة داخل قالب HTML الأصلي
├── templates/
│   └── quiz_template.html   # القالب الأصلي (نفس تصميمك، بدون أي تعديل)
├── requirements.txt
├── .env.example
└── README.md
```

## 2. متطلبات التشغيل

- Python 3.10 أو أحدث
- توكن بوت تليجرام (من [@BotFather](https://t.me/BotFather))
- مفتاح واحد على الأقل من Gemini API (مجاني من
  [Google AI Studio](https://aistudio.google.com/app/apikey))

### الحصول على توكن تليجرام
1. افتح محادثة مع [@BotFather](https://t.me/BotFather)
2. أرسل `/newbot` واتبع التعليمات
3. انسخ التوكن الذي يعطيك إياه (شكله: `123456789:ABCdefGhIJKlmNoPQRsTuVwXyZ`)

### الحصول على مفتاح Gemini
1. ادخل على [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey)
2. اضغط "Create API Key"
3. انسخ المفتاح

💡 **يمكنك إضافة أكثر من مفتاح** (من نفس الحساب أو حسابات مختلفة) مفصولين
بفاصلة، والبوت سيبدّل تلقائيًا بينهم عند وصول أي مفتاح لحد الحصة المجانية.

## 3. خطوات التشغيل

```bash
# 1. إنشاء بيئة افتراضية (اختياري لكن يُفضّل)
python3 -m venv venv
source venv/bin/activate      # على ويندوز: venv\Scripts\activate

# 2. تثبيت المكتبات
pip install -r requirements.txt

# 3. إعداد ملف البيئة
cp .env.example .env
# افتح ملف .env وحط فيه التوكن والمفاتيح الحقيقية

# 4. تشغيل البوت
python bot.py
```

لو كل حاجة مظبوطة، هتشوف في الطرفية:
```
🚀 البوت شغّال الآن (polling)...
```

افتح تليجرام، دور على البوت بتاعك، وابعتله `/start`.

## 4. طريقة استخدام البوت (من ناحية الطالب/المستخدم)

1. `/start`
2. يبعت مصدر: رابط يوتيوب، أو يرفع صورة/PDF/HTML/ملف صوتي
3. البوت يستخرج المحتوى ويعرض مقتطف منه، ويسأل: تكمل بيه زي ما هو، ولا
   تضيف/تصحح حاجة؟ (لو اختار "عدّل"، يبعت ملاحظاته كنص ويُؤخذ في الاعتبار
   وقت توليد الأسئلة)
4. يسأل: كام سؤال عاوز؟ (يقدر يكتب رقم أو يضغط زر جاهز)
5. يسأل: امتحان مفتوح ولا بوقت محدد؟ لو مؤقت، يسأل كمان عن المدة بالدقائق
   (زر جاهز أو رقم حر)
6. البوت يحلل المحتوى بالذكاء الاصطناعي ويولّد الأسئلة (وللكويزات الكبيرة
   يقسّم التوليد لدفعات تلقائيًا لتقليل احتمال الفشل)، وقد يولّد رسومًا
   توضيحية بسيطة (SVG) لبعض الأسئلة التي تستفيد منها
7. أثناء تفريغ أي ملف صوتي، يعرض البوت مؤشر تقدّم تقريبي (وقت منقضي + نسبة
   تقديرية) بدل رسالة ثابتة
8. يبعت ملف `quiz.html` جاهز — الطالب يفتحه في أي متصفح ويبدأ الاختبار فورًا

## 5. ملاحظات تقنية مهمة

### أ. لماذا التصميم لم يتغير؟
الكود لا يلمس تصميم أو تنسيق القالب الأصلي إطلاقًا. كل ما يفعله
`html_builder.py` هو استبدال محتوى وسمين `<script type="application/json">`
موجودين أصلًا داخل ملفك (`embeddedQuestionsData` و `embeddedExamSettings`)
— بنفس الطريقة التي تستخدمها ميزة "تحميل نسخة مدمجة" الموجودة أصلًا
في الملف نفسه.

### ب. لماذا Transcript API لليوتيوب وليس تحميل الفيديو؟
جلب الترجمة النصية (transcript) مباشرة أسرع وأخف بكثير من تحميل الفيديو
وتفريغه صوتيًا، وهو ما طلبته كأولوية. **قيود معروفة:**
- يعمل فقط مع الفيديوهات التي تحتوي ترجمة نصية (تلقائية أو يدوية) مفعّلة
- لو الفيديو transcript معطل عليه، البوت هيبلغك بده صراحة

### ج. الرسوم التوضيحية (مفعّلة الآن)
عند توليد الأسئلة، يقرر Gemini لكل سؤال هل يستفيد من رسم توضيحي بصريًا
(حقل `needs_image` — لنسبة قليلة من الأسئلة فقط، زي الهندسة أو مخططات
نحوية). بعد اكتمال وتصحيح كل الأسئلة، يتم عمل استدعاء *منفصل* لـ Gemini
لكل سؤال من دول (بحد أقصى `MAX_IMAGES_PER_QUIZ`) لتوليد SVG بسيط وآمن
(بدون `<script>` أو روابط خارجية)، يتحول لـ data URI ويُحقن مباشرة في
الملف — فمفيش استضافة خارجية ولا روابط ممكن تنتهي صلاحيتها.

ملاحظة مهمة: كان في خطأ في القالب الأصلي نفسه — دالة `validateQuestion`
في الـ JS كانت بتقرأ حقل `image` بس (وتشترط رابط http/https)، بينما البوت
كان بيكتب `imageUrl`، فأي صورة كانت هتتجاهل بصمت حتى لو اتفعّلت. تم تصحيح
الدالة عشان تقبل الاسمين (`image` أو `imageUrl`)، وتقبل كمان الـ data URI
الخاص بالصور المولّدة تلقائيًا، من غير أي تغيير في شكل أو تصميم القالب.

تقدر تعطّل الميزة دي بالكامل بضبط `ENABLE_QUESTION_IMAGES=false` في `.env`.

### د. حدود الأسئلة
- الحد الأدنى: 3 أسئلة
- الحد الأقصى: 40 سؤال
- الافتراضي المقترح للمستخدم: 10 / 15 / 20 / 30 (أزرار جاهزة) أو أي رقم يكتبه يدويًا

### هـ. حجم الملفات
تليجرام يحدد حجم الملفات التي يستقبلها البوت العادي بحد أقصى **20 ميجابايت**.
الملفات الأكبر من كده (فيديوهات طويلة كملف صوتي مثلاً) لازم تتقسم أو تُرفع
كرابط بدلاً من ملف مباشر.

## 6. النشر على استضافة سحابية (لاحقًا)

المشروع مبني بطريقة `polling` (البوت يسأل تليجرام باستمرار عن رسائل جديدة)
وهي أبسط طريقة للتشغيل، وتصلح للتشغيل على أي منصة زي Render أو Railway
كـ **Background Worker** (مش Web Service) لأنها مش محتاجة تستقبل HTTP
من الخارج. لما تكون جاهز للنشر، غالبًا هتحتاج فقط:
- ملف `Procfile` أو إعداد "Start Command": `python bot.py`
- إضافة متغيرات البيئة (`TELEGRAM_BOT_TOKEN`, `GEMINI_API_KEYS`) في إعدادات
  المنصة نفسها بدل ملف `.env`

## 7. استكشاف الأخطاء الشائعة

| المشكلة | الحل المحتمل |
|---|---|
| `لم يتم ضبط TELEGRAM_BOT_TOKEN` | تأكد إن ملف `.env` موجود ومكتوب فيه التوكن صح |
| `فشلت كل المفاتيح المتاحة` | تحقق من صحة مفاتيح Gemini، أو أضف مفتاح جديد |
| `الترجمة النصية معطّلة على هذا الفيديو` | جرّب فيديو آخر عليه ترجمة نصية (CC) مفعّلة |
| `تعذّرت قراءة ملف الـ PDF` | الملف غالبًا صور ممسوحة ضوئيًا بدون نص فعلي (يحتاج OCR إضافي لاحقًا) |
